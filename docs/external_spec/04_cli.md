# 04. CLI 仕様

## 1. コマンド体系

```
runbook [--version] <subcommand> ...

runbook run      [オプション] <手順書.md>   実行
runbook list     [--detail] [--var ...] <手順書.md>    ステップ一覧表示
runbook check    [--preview] [--var ...] <手順書.md>   静的検証(実行しない)
runbook renumber [--var ...] <手順書.md>    ## 見出しへの連番付与(ファイル書き換え)
```

- サブコマンドは必須。`--version` は `runbook 0.4.0` 形式を表示して終了。
- 全サブコマンド共通の引数:
  - `file`(位置引数、必須): 手順書 Markdown ファイルのパス
  - `--var KEY=VALUE`(複数回指定可): 手順書変数の指定/上書き。`=` を含まない値は
    エラー。KEY は前後空白をトリム、VALUE は最初の `=` 以降すべて(`=` を含んでよい)

### run のオプション

| オプション | 意味 |
|---|---|
| `-i`, `--interactive` | 逐次インタラクティブ実行。各ステップ実行前に確認プロンプトを出す(§3.3) |
| `--only SPEC` | 実行するステップ番号の指定。`1,3-5` 形式(カンマ区切り、`N` または `N-M`)。書式不正・範囲外(1〜総数)はエラー |
| `--from N` / `--to N` | 開始/終了ステップ番号。`--only` の結果と**積集合**を取る。範囲外(1 <= from <= to <= 総数 を満たさない)はエラー |
| `--start-from N` | ステップ N から最後まで**再開実行**する。`--only` / `--from` / `--to` と併用不可(エラー)。範囲外はエラー。直近実行の環境変数を復元する(§4) |
| `-y`, `--yes` | 実行前サマリーの確認ゲートをスキップ(非対話実行用) |
| `--operator NAME` | 作業者名。省略時は実行開始時に入力を求める(必須項目) |
| `--checker NAME` | 確認者名(任意) |
| `--log-dir DIR` | ログ保存先ディレクトリ(既定 `./logs`) |

選択の結果、実行対象ステップが 0 になった場合はエラー(「実行対象のステップがありません」)。

## 2. 終了コード

| コード | 条件 |
|---|---|
| 0 | 正常終了(run: 全対象ステップが OK またはユーザースキップで完走 / check: 問題なし(警告のみは 0)/ list・renumber: 成功) |
| 1 | run: ステップの失敗(判定 NG・タイムアウト・基準式エラー)による中断 / check: パースエラーまたは基準式エラー検出 |
| 2 | パースエラー・引数エラー(ParseError / ValueError 相当。argparse の用法エラーも 2) |
| 130 | run: 確認ゲートでの中止、インタラクティブ/手動ステップでの作業者中断(q)、Ctrl-C |

## 3. run の実行フロー

処理順序:

1. 手順書パース(02 章)。
2. 対象ステップ選択(`--only` / `--from` / `--to` / `--start-from`)。
3. `--start-from` の場合、復元元 env_overlay.sh を検索(§4)。
   見つからなければ**実行前にエラー**(fail-loud。環境なしで実行してよい場合の
   `--from N` を案内)。
4. **実行前サマリー表示**(§3.1)→ 確認ゲート(§3.2)。中止なら**ログディレクトリを
   作らずに** exit 130。
5. 作業者名・確認者名の取得(§3.5)。
6. ログディレクトリ作成(→ 05 章)、実行開始情報の表示・記録。
7. ステップを記載順に処理(選択外の番号は表示・記録なしで読み飛ばす)。
   各ステップの処理は §3.3〜3.4 および 05 章。
8. 失敗(NG / エラー)または作業者中断が起きたら**即座にループを打ち切る**。
9. 終了処理: 集約ホストマトリックス表示(→ 05 章 §6)、result.json 確定、
   実行結果サマリー(完了 / スキップあり完了 / 実行中断)、ステップ別リザルト一覧、
   ログ保存先の表示。

### 3.1 実行前サマリー

以下を行ベースのツリー表示で出す(手順書・環境の取り違えに気付くためのゲート):

- 手順書タイトルとファイルパス
- モード(「一括」/「逐次インタラクティブ」)
- 実行対象: 「n/総数 ステップ(うち手動 m)」+ 対象ステップの番号・タイトル一覧
  (手動ステップには「(手動)」を付す)
- 変数一覧(secrets 宣言された変数の値は `*****` でマスク)
- secrets がある場合: 秘匿変数名の一覧と、
  「export した値は env_overlay.sh に平文で残る」旨の注意(環境変数の
  引き継ぎは常時有効なため無条件に表示する)
- 使用インベントリ一覧(対象ステップの ansible 系設定・行内指定から収集した
  重複排除済みリスト)
- `--start-from` の場合: 再開開始ステップと環境変数の復元元

### 3.2 確認ゲートと入力規則

- プロンプト「上記の内容で実行しますか? [y=実行 それ以外=中止]」。
  **`y` / `yes`(大文字小文字非区別)のみ実行**、それ以外の入力はすべて中止(exit 130)。
- `--yes` 指定時はサマリー表示のみ行い、ゲートを省略する。
- 標準入力が EOF(非対話環境)の場合は「--yes を指定してください」と表示して中止。

### 3.3 逐次インタラクティブ実行(-i)

コマンドステップごとに、ステップヘッダ表示後に確認プロンプトを出す:

- `Enter` / `r` / `run` / `y` → 実行
- `s` / `skip` → スキップ(状態 `skipped`・詳細「操作者がスキップ」で記録し、次のステップへ)
- `q` / `quit` / `abort` → 中断(状態 `skipped`・詳細「操作者が中断」で記録し、
  実行全体を aborted・exit 130 で終了)
- 上記以外の入力は再プロンプト。EOF は q と同じ(端末必須の旨を表示)。

### 3.4 手動ステップの完了確認

手動ステップ(RB-CMD なし)では、説明を表示して完了確認プロンプトを出す
(一括実行でも対話が必要。**手動ステップを含む手順書は端末からの実行が必須**):

- `y` / `yes` / `done` → 完了。状態 `ok`、詳細「作業者(名前)が完了を確認」、
  確認時刻を記録して次のステップへ。**Enter 空打ちでは完了しない**(誤続行防止)。
- `s` / `skip` → スキップ(**-i のときのみ**選択肢に出る)
- `q` / `quit` / `abort` → 中断(状態 `skipped`・詳細「操作者が中断(手動ステップ未完了)」、
  RB-ONFAIL があれば表示、aborted・exit 130)
- EOF は q と同じ。

### 3.5 作業者・確認者

- `--operator` 指定時: プロンプトなし。確認者は `--checker`(未指定なら空)。
- 未指定時: 作業者名を必須入力(空入力は再プロンプト、EOF はエラーで
  `--operator` を案内)。続けて確認者名を任意入力(Enter でスキップ。
  `--checker` が指定済みならプロンプトしない)。
- 両者は実行開始表示・run.log・result.json に記録される。

## 4. --start-from の環境変数復元

`--start-from N` で再開する場合(環境変数の引き継ぎは常時有効):

- `--log-dir` 配下から、ディレクトリ名が `<手順書名(拡張子なし)>_YYYYMMDD_HHMMSS`
  (同一秒衝突時の `_2` 等の連番付きも可)に**厳密一致**するものを名前降順(= 新しい順)に
  探し、最初に `env_overlay.sh` を含むディレクトリのそれを復元元とする。
  (名前の厳密照合により、`proc` の検索で `proc2_...` を誤って拾わない。)
- 復元元を今回のログディレクトリの `env_overlay.sh` に**コピー**してから実行を開始する
  (前回実行分は改変しない)。
- 復元元はサマリー・実行開始表示・run.log に表示し、result.json に
  `resumed_env_from` として記録する。

## 5. list

手順書をパースし、ステップ一覧を表(No. / ステップ / 種別 / 正常性基準)で表示する。

- 表はどの列も切り詰めない。コマンドは列に入れない(表の幅では必ず切り捨てが
  必要になり、折り返してもパスが単語途中で分断されて読めないため)。
  コマンド全文は `--detail` で表示する。
- 種別欄は `bash` / `ansible` / `playbook` / `手動`。
- 手動ステップは基準欄「作業者の完了確認」。
- `--detail` を付けると、一覧表に続けて各ステップの詳細(説明・対象・コマンド・
  変数展開後の実行コマンド・正常性基準)を全文表示する(表示要素は 05 章 §3)。
  表示内容は `check --preview` の第2部と同一。
- secrets の値はマスクして表示する。

## 6. check

実行せずに検証する。判定は 3 段階:

1. **パースエラー**(02 章)→ `NG <メッセージ>` を表示して exit 1。
2. **基準式エラー**: 全ステップ(手動ステップ除く)の基準式を
   静的検証(03 章 §6)し、エラーがあれば
   `NG <ラベル>ステップN「タイトル」(L行番号): <メッセージ>` を列挙して exit 1。
3. **警告**(実行は妨げない。表示して exit 0):
   - 見出し番号と実際の順序の不一致(renumber を案内)
   - 参照パスの存在チェック: ansible 系ステップのインベントリ
     (カンマを含む値はインラインホストリストとしてスキップ)、
     playbook 行内の `*.yml` / `*.yaml` トークン(`-e @vars.yml` の `@` は外して解釈。
     ヒューリスティックであり引数列の完全解釈はしない)、RB-LOCALDEF の cwd。
     存在しないものを警告する。**エラーではなく警告**とするのは、check 時と実行時で
     カレントディレクトリが異なると誤検知になり得るため(同一ファイルへの重複警告は
     除去する)。
   - 共通設定(```runbook フェンス)の未知キー。互換のため解析自体は通すが、
     書いた側は効いていると誤解するため警告する。`timeout` は特に
     「共通設定では効かず、既定はタイムアウトなし(無制限に待つ)」ことと
     RB-LOCALDEF へ書くべきことを併せて案内する。
   - 見出しはあるが本文が空の RB-ONFAIL / RB-DESCRIPTION。内容をコードフェンスで
     囲むと本文が捨てられるため(自由記述セクションはフェンス外に書く)。
     特に RB-ONFAIL は失敗して中断した瞬間にしか表示されず、空でも気付けない。

最後に `OK <パス>: n ステップ、書式・基準式に問題ありません
[(警告 k 件)]` を表示する。

### check --preview

検証後、変数展開・ansible コマンド組み立て後の**実行コマンド全文**を、
ansible / playbook ステップでは実行先(`対象: <ターゲット> @ <インベントリ>`)と
併せてステップごとに表示する(表示要素は 05 章 §3)。手動ステップは
「(手動ステップ: 作業者の完了確認のみ)」。基準式も表示する。secrets はマスクする。

## 7. renumber

`## ` 見出しに実行順の連番を「`## N. タイトル`」形式で付与・振り直し、
**ファイルを書き換えて保存する**(一般的な Markdown プレビューでステップが
番号付きで見えるようにするための機能)。

- まず通常のパースを行い、**パースエラーがあればファイルを書き換えない**。
- フェンス内の行・`###` 以下の見出しは対象外。
- 既存の見出し番号(`1.` `2．` `3:` 等)は正しい順序の `N. ` に置き換わる。
  タイトル部分は変更しない。
- 完了時に「n ステップ中 m 見出しを更新しました」を表示する。
- 出力ファイルは行を `\n` で結合し末尾に改行 1 つ。

## 8. エラー表示の共通規則

- ParseError / ValueError 相当は `エラー: <メッセージ>` を表示して exit 2
  (check のみ独自の NG 表示で exit 1)。
- Ctrl-C(KeyboardInterrupt)は「中断されました」を表示して exit 130。
- ターミナル出力は soft-wrap(強制折り返しなし)の行ベース形式とする(01 章 §2)。
