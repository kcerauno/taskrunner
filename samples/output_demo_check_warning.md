# check 警告デモ(RB-ONFAIL が黙って捨てられる書き方)

**このファイルは意図的に誤った書き方をしています。**
`runbook check` が警告を出すことを確認するためのサンプルです。

```
runbook check samples/output_demo_check_warning.md
```

期待される出力:

```
警告 ステップ1「...」: RB-ONFAIL の内容が空です(コードフェンス ``` の中に
     書かれている可能性があります。RB-ONFAIL はフェンスなしで記述してください)
OK samples/output_demo_check_warning.md: 2 ステップ、書式・基準式に問題ありません(警告 1 件)
```

**なぜ警告が必要か**

`RB-ONFAIL` / `RB-DESCRIPTION` は自由記述セクションで、**コードフェンスの外**に書く。
フェンスで囲むと本文が捨てられ、`RB-ONFAIL` は空になる。

`RB-ONFAIL` は「失敗して中断した瞬間」にしか表示されないため、空だと気付く機会が
実質的に存在しない。最も困っているときにガイダンスが出ないという事故になるので、
`check` の時点で警告する。

正しい書き方はステップ2、誤った書き方はステップ1。
`runbook run` すると**ステップ1で失敗し**、ガイダンスが出ないことも確認できる
(ステップ2は実行されない)。

## 1. 誤り: RB-ONFAIL をフェンスで囲んでいる(警告が出る)

### RB-CMD
```bash
echo "checking"
false
```

### RB-EXPECTED
```
rc == 0
```

### RB-ONFAIL
```
この文章はコードフェンスの中にあるため捨てられ、失敗しても表示されない。
```

## 2. 正しい: RB-ONFAIL をフェンスなしで書いている(警告は出ない)

### RB-CMD
```bash
echo "checking"
```

### RB-EXPECTED
```
rc == 0
```

### RB-ONFAIL
この文章はフェンスの外にあるので、失敗時にガイダンスとして表示される。
担当へ連絡し、影響範囲を確認する。
