# 出力の可読性改善案(情報量を減らさない前提)

対象: `runbook list` / `runbook check --preview` / `runbook run` のコンソール出力
関連コード: [runbook/render.py](../runbook/render.py), [runbook/cli.py](../runbook/cli.py)

前提として **表示する情報は一切減らさない**。現状の問題は情報量ではなく、
「表の幅制約」と「1行が長すぎること」の2つに集約される。

---

## 現状の問題(実測)

`.venv/bin/runbook check --preview samples/sample_ansible.md` の出力を幅80で確認した結果。

### 問題1: コマンドが60文字で切り捨てられ、復元不能

[render.py:127-128](../runbook/render.py#L127-L128)

```python
cmd = mask(s.command)
cmd = cmd if len(cmd) <= 60 else cmd[:57] + "..."
```

これは折り返しではなく**情報の破棄**。列には `overflow="fold"` が指定済み
([render.py:121](../runbook/render.py#L121))なので、切り捨てなければ Rich が
全文を折り返せる。`list` にはこの表しか無いため、`list` 単体ではコマンド全文を
確認する手段が存在しない(今回の指摘の直接原因)。

### 問題2: ステップ名まで `…` で切られている

`ステップ` 列に `overflow` 指定がないため Rich の既定(ellipsis)が効き、
実測で `全webサーバの稼働確 …` / `DBサーバのディスク確…` と欠落した。
コマンド列が幅を占有しているほど、この欠落が悪化する。

### 問題3: 「実行コマンド」が1行130文字超

```
実行コマンド: ansible -e '{"INVENTORY": "./samples/local_test/inventory.ini"}' webservers -i ./samples/local_test/inventory.ini -m shell -a uptime
```

`soft_wrap=True` ([render.py:17](../runbook/render.py#L17))は tee 保存時に行を
壊さないための正しい選択だが、その結果ターミナル側で任意位置に折り返され、
`│` のガター(罫線)が失われて構造が読めなくなる。

### 問題4: 引数順がスタイル間で不統一

同じ意味のコマンドが、記述スタイル依存で `-e` の位置が変わる。

| ステップ | 生成される順序 |
|---|---|
| 1(行内指定) | `ansible -e '{...}' webservers -i ... -m shell -a uptime` |
| 2(RB-LOCALDEF) | `ansible db01 -i ... -e '{...}' -m shell -a 'df -h'` |

ステップ間を目で見比べる際のノイズになる。出力側ではなくコマンド組み立て側の問題。

---

## 改善案

### 案1 ★最優先: 一覧表から「コマンド」列を外し、全列を fold にする

表の役割を「俯瞰(何番・何をする・合否条件)」に限定し、コマンド全文は
第2部の詳細ブロックに任せる。これで切り捨てが全て消える。

**変更点** — [render.py:117-130](../runbook/render.py#L117-L130) の `step_table`
- `コマンド` 列を削除し、代わりに `種別`(runner)列を追加
- `ステップ` 列に `overflow="fold"` を指定
- 60文字切り捨てロジックを削除

**実測結果**(この案を実際に走らせた出力):

```
  No.   ステップ                       種別      正常性基準
 ──────────────────────────────────────────────────────────────────────────────
    1   全webサーバの稼働確認(行内指   ansible   rc == 0 and
        定スタイル)                              out("CHANGED|SUCCESS") and
                                                 not out("UNREACHABLE|FAILED")
    2   DBサーバのディスク確認(RB-LO   ansible   rc == 0 and not out("
        CALDEF スタイル)                         100%|UNREACHABLE|FAILED")
```

切り捨てゼロ。`種別` が入るのでどのステップが manual / ansible / playbook かも
一覧で分かる(現状は「(手動ステップ)」を見るまで分からない)。

**却下した対案**: 切り捨てだけをやめて `コマンド` 列を fold させる案も試したが、
幅22文字に押し込まれてパスが `./samples/local_test/i` / `nventory.ini` と
単語途中で分断され、案1より明確に読みにくかった。列を残す選択は取らない。

### 案2: `list` に詳細ブロックを出せるようにする

`check --preview` の第2部([cli.py:646-651](../runbook/cli.py#L646-L651))が
既に「省略なしの全文表示」を実現しており、`show_step_header` として部品化もされている。
`list` からも同じものを出せば、「確認したいだけ」の用途で `check` を経由する必要がなくなる。

- `runbook list --detail`(または `--full`)で表 + 詳細ブロックを出力
- 実装は `cmd_list` に3行足すだけ:
  ```python
  if args.detail:
      for s in proc.steps:
          show_step_header(s, len(proc.steps), mask, preview=True)
  ```

案1で表から情報が減る分、これは同時に入れるべき。両方入れて初めて
「情報量を減らさず見やすく」が成立する。

### 案3: 実行コマンドをオプション境界で折り返す

長い1行を、シェルの行継続(`\`)を使ってオプション単位に分ける。
**文字列としての情報は完全に同一**で、コピペしてもそのまま動く。

```
  ├ 実行コマンド:
  │   ansible webservers \
  │     -i ./samples/local_test/inventory.ini \
  │     -e '{"INVENTORY": "./samples/local_test/inventory.ini"}' \
  │     -m shell \
  │     -a uptime
```

利点:
- ターミナル幅に依存せず構造が保たれる(ガターが消えない)
- ステップ間の差分が縦に揃うので目視比較が容易
- 証跡ファイルに残したとき diff が取りやすい

**実装上の注意(試作して判明)**: 既存の `parser._tokenize`
([cli.py:581](../runbook/cli.py#L581) が流用しているもの)を使って分割・再結合すると
**クォートが失われる**。試作では `-a 'df -h'` が `-a df -h` に、
`-e '{...}'` が `-e {...}` になり、コピペで動かないコマンドになった。
折り返しは `_tokenize` を通さず、元文字列上でクォート状態を追いながら
` -x ` の境界を探して改行を挿入する実装にする必要がある。

### 案4: 定型部分と可変部分をスタイルで区別する

現状 `実行コマンド` は全体が一律 `dim`([render.py:57](../runbook/render.py#L57))。
全ステップに同じ `-e '{"INVENTORY": ...}'` と `-i <同じパス>` が繰り返し現れるため、
ステップ間で実際に違う部分(ターゲット、`-m`、`-a`)が埋もれる。

- 定型(`-e` の変数JSON、`-i`)は `dim` のまま
- 可変(ターゲットホスト、`-m` モジュール、`-a` 引数)は通常輝度または cyan

文字は一切削らず、視線誘導だけを変える。案3と組み合わせると効果が大きい。

### 案5: 文書冒頭に共通コンテキストを1回だけ出す

`check --preview` / `list` の先頭で、`runbook` フェンスの vars と対象インベントリを
1回まとめて表示する。各ステップの `-e '{...}'` は残したまま、読み手が
「これは共通設定の反映」と即座に理解できるようにする。

```
・ 共通設定: INVENTORY=./samples/local_test/inventory.ini
・ 対象インベントリ: ./samples/local_test/inventory.ini (2 ステップが参照)
```

### 案6: 引数順を正規化する(出力ではなくコマンド組み立て側)

問題4の解消。記述スタイルに関わらず
`ansible <target> -i <inventory> -e <vars> -m <module> -a <args>` の順に固定する。
挙動は変わらず(ansible のオプションは順序非依存)、出力の縦の揃いが改善する。
ただし既存テストが生成コマンド文字列を検証している可能性があるため、
[tests/test_parser.py](../tests/test_parser.py) / [tests/test_cli.py](../tests/test_cli.py)
の期待値追従が必要。

### 案7: 機械可読出力を別系統で足す(任意)

人間向け出力を一切変えずに済む追加策として `--format json` を用意する。
差分レビューや外部ツール連携では、整形済みテキストより構造化データのほうが確実。
人間向け整形(案1〜5)とは目的が違うので、どちらかで代替はできない。

---

## 推奨する適用順

| 順 | 案 | 効果 | 変更規模 |
|---|---|---|---|
| 1 | 案1 表の切り捨て廃止・列構成変更 | 情報欠落をゼロにする(必須) | 小(`step_table` のみ) |
| 2 | 案2 `list --detail` | `list` で全文が見られるようになる | 小(既存部品の再利用) |
| 3 | 案3 コマンドのオプション境界折返し | 長いコマンドが構造的に読める | 中(クォート対応の実装が要) |
| 4 | 案4 定型/可変のスタイル分け | ステップ間の差分が目立つ | 小 |
| 5 | 案5 共通コンテキストの先出し | 繰り返しの意味が分かる | 小 |
| 6 | 案6 引数順の正規化 | 縦の揃い / テスト追従が必要 | 中(テスト修正含む) |
| 7 | 案7 `--format json` | 人間向け出力と独立した用途 | 中 |

案1と案2は一組で入れる前提。案1単独では表からコマンドが消えるだけになる。

## 補足: 検証済みでない点

- 案3の「クォートを保ったまま折り返す」実装は**未実装**。試作で `_tokenize`
  経由が使えないことまでを確認した段階。
- 案6の影響範囲(既存テストが生成コマンド文字列に依存しているか)は**未確認**。
- 幅の実測は幅80(非TTY時の Rich 既定)で行った。実際のターミナル幅が広い環境では
  問題2の `…` 欠落は軽減されるが、問題1の60文字切り捨ては幅に関係なく常に発生する。
