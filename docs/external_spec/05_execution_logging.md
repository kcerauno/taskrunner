# 05. 実行モデルとログ成果物

## 1. コマンド実行の仕様

- コマンド列(ステップの RB-CMD から組み立てた 1 文字列。複数行可)は
  **`/bin/bash -c` で 1 プロセスとして実行**する。
- 標準入力は**閉じて**実行する(対話プロンプトを出すコマンドが無限待ちにならないため)。
- 標準出力・標準エラーは**行単位でリアルタイムにターミナルへ中継**しつつ全量を捕捉する
  (stderr 行は赤で表示。表示時はシークレットマスク §5 を適用。判定・生ログ保存は
  マスク前の生出力に対して行う)。デコード不能バイトは置換文字に置き換える。
- プロセスは新しいセッション(プロセスグループ)で起動する。
- `timeout`(RB-LOCALDEF)超過時は**プロセスグループごと SIGKILL** し、
  ステップを状態 `error`・詳細「タイムアウト(N s)により強制終了」とする。
- `cwd`(RB-LOCALDEF)指定時はそのディレクトリで実行する。
- 終了コード・所要時間(秒、小数第 3 位まで)を記録する。

## 2. ステップの状態と判定

各ステップの実行結果は次のいずれかの状態を取る:

| 状態 | 条件 |
|---|---|
| `ok` | 正常性基準の評価結果が真。または手動ステップの完了確認 |
| `ng` | 基準の評価結果が偽(詳細「正常性基準を満たしませんでした」) |
| `error` | タイムアウト、または基準式の評価エラー(詳細にエラーメッセージ) |
| `skipped` | 操作者によるスキップ/中断(-i の s、手動ステップの q など) |

- 判定はコマンド終了後、**生の(マスクしていない)** rc・stdout・stderr に対して
  基準式(03 章)を評価して行う。
- `ok` → 次のステップへ続行。
- `ng` / `error` → **即中断**: 詳細表示、判定内訳(NG かつ条件 2 つ以上のとき。03 章 §5)、
  RB-ONFAIL ガイダンス(あれば)を表示し、実行全体を `aborted`・exit 1 で終える。
- 選択外ステップ(--only 等)は表示も記録もしない(result.json にも現れない)。

## 3. ターミナル出力(ステップ表示)

行ベースのツリー形式(`・` `├` `│` `└`)。1 ステップの表示要素は順に:

1. `・ ステップ N/総数: タイトル`
2. `説明:`(RB-DESCRIPTION があれば)
3. コマンド表示(ランナー別):
   - shell: `コマンド:` + 各行を `$ ` 付きで表示
   - ansible: `コマンド (ansible ad-hoc / shellモジュール):` + リモートコマンド各行
     (`$ ` 付き)+ `実行コマンド:` として組み立て後の全文(dim 表示)
   - playbook: `プレイブック (ansible-playbook):` + 各行 + `実行コマンド:` 全文
   - manual: `手動ステップ(コマンドなし。上記の作業を実施してください)`
4. `正常性基準: <式>`(手動ステップ以外)
5. `開始: YYYY-MM-DD HH:MM:SS`
6. 出力行の中継(`│` プレフィックス付き)
7. (host_matrix 有効の ansible/playbook ステップ)`ホスト別結果: web01=O db01=X` の
   1 行表示(§6)。凡例は**最初の 1 回のみ**表示する
8. 結果行(終了時刻を含める。独立した「終了:」行は出さない):
   - OK: `└ 結果: ✓ Completed (rc=N, T s, 終了 HH:MM:SS)`
     (手動ステップは `(手動確認 <時刻>)`)
   - NG: `詳細:` + 判定内訳(該当時)+
     `└ 結果: ✘ Failed (rc=N, T s, 終了 HH:MM:SS)` +
     `失敗したため、実行を中断します。` + RB-ONFAIL(該当時)

開始のタイムスタンプは実行前に表示する(長時間ステップで実行中であることを示すため)。
終了時刻は結果行にまとめる。日付は実行開始ヘッダに出ているため時刻のみとし、
日を跨いだ場合のみ日付を併記する。パネル・罫線囲みは使わず、
長い行も折り返さない(テキストログ保存を想定)。

出力行の中継では、構造を示す行のみ色を付ける(文字は変えない): ansible の
ホスト区切り行(`<host> | CHANGED|SUCCESS|OK |` は緑、`FAILED` / `UNREACHABLE` は赤)、
playbook の `PLAY` / `TASK` / `PLAY RECAP` 見出し、`failed=` / `unreachable=` が
1 以上の RECAP 行(赤)。それ以外の本文は既定のまま。

## 4. ステップ間の環境変数引き継ぎ

**常時有効**(設定で切り替えない)。v0.4.0 の `share_env` オプションは v0.5.0 で廃止され、
方式も「`export -p` の全保存」から「baseline + 差分オーバーレイ」に変わった。

- **baseline**: runbook 親プロセスが実行開始時に持っていた環境変数一式(実行中は不変)。
- **オーバーレイ**: baseline との差分。`sets`(export する変数)と
  `unsets`(unset する変数 = tombstone)を持つ。各ステップの初期環境は
  「baseline にオーバーレイを適用したもの」。
- 各ステップ終了直後に `env -0` で export 済み変数一式(スナップショット)を捕捉し、
  baseline と比較してオーバーレイを**丸ごと再生成**する(追記ではない)。
  これにより、あるステップで `unset` された変数が次のステップで復活しない。
- `SHLVL` / `PWD` / `OLDPWD` / `_` は bash・OS が毎回書き換えるノイズのため差分から除外する
  (オーバーレイに載せると cwd 指定と矛盾するため)。
- コマンド本体の途中で `exit` した場合やタイムアウト・中断シグナルを受けた場合は
  ラッパー末尾に到達せずスナップショットを捕捉できないため、その回のオーバーレイ更新は
  行われない(仕様)。
- オーバーレイはステップ終了ごとにログディレクトリの `env_overlay.sh` へ書き出す。
  形式は `export KEY=VALUE` / `unset KEY` の行のみ。
- `--start-from` での復元は 04 章 §4。
- `env_overlay.sh` は**実行に必要なため平文**であり、マスキング(§5)を適用しない。
  そのためサマリーでは secrets 宣言がある場合に無条件で注意を表示する。
  アトミック書き込み(同一ディレクトリの一時ファイル + rename)を経由するため、
  結果としてパーミッションは `0600` になる(result.json も同様。run.log は追記なので
  umask に従う)。

## 5. シークレットマスキング(secrets)

共通設定 `secrets: [VAR, ...]` で宣言した変数の**値**を、表示・ログ出力の
あらゆるテキストから `*****` に置換する。

- 対象: ターミナル表示(サマリーの変数値・コマンド表示・出力中継・判定内訳)、
  run.log、result.json(全文字列を再帰的にマスク)、stepNN_stdout/stderr.txt、
  list の表、check --preview。
- 非対象: 正常性基準の**評価**(生出力に対して行う)、env_overlay.sh(§4)。
- 置換は**値が長いものから順に**行う(ある値が別の値の部分文字列である場合の
  取りこぼし防止)。値が空の変数は無視する。
- 宣言変数が未定義の場合はパースエラー(02 章 §4)。

## 6. ホスト別結果マトリックス(ansible 系)

ansible / playbook ステップでは、コマンド出力(stdout + stderr)からホストごとの
結果を抽出して記録する:

- ad-hoc: 行頭 `<ホスト名> | <STATUS>` 形式の行を解析。
  `CHANGED` / `SUCCESS` → `ok`、`FAILED` → `failed`、`UNREACHABLE` → `unreachable`。
- playbook: `PLAY RECAP` のホスト行
  (`<ホスト名> : ok=N changed=N unreachable=N failed=N ...`)を解析。
  `failed>0` → `failed`、それ以外で `unreachable>0` → `unreachable`、他は `ok`。
  複数の RECAP(複数行実行)は同一ホストをマージ(後勝ち)。
- 抽出結果は host_matrix 設定の有無に関わらず**常に** result.json の `host_results` に
  記録する(`{ホスト名: "ok"|"failed"|"unreachable"}`)。

`ansible: {host_matrix: true}` のステップでは、ステップ終了時に
`ホスト別結果: <ホスト名>=<マーク> ...`(ホスト名ソート順)を **1 行**で表示する
(1 ステップ分は 1 次元のため表を組まない。run.log と同じ表記)。
ホスト数が多く 1 行に収まらない場合のみ、列 = ホスト名の表にフォールバックする:

- マーク(半角限定): `O` = 成功、`X` = 失敗、`!` = 到達不能、`-` = 対象外(結果なし)。
  凡例は最初のステップと最終マトリックスにのみ表示する(毎ステップ繰り返さない)。
- run.log には `ホスト別結果: web01=O web02=X ...` の 1 行形式で記録する。
- host_matrix 有効かつ結果のあるステップが **2 つ以上**実行された場合、実行終了時に
  **行 = ステップ(`N: タイトル`)、列 = 全ホストの和集合**の
  「最終ホスト別結果マトリックス」を表示する。

## 7. ログ成果物

### 7.1 ログディレクトリ

- 実行 1 回ごと(確認ゲート通過後)に `<--log-dir>/<手順書名>_<YYYYMMDD_HHMMSS>/` を
  作成する。手順書名はファイル名(拡張子なし)。
- 同一秒内の連続実行で名前が衝突する場合は `_2`, `_3`, ... を付けて
  **必ず新規ディレクトリを作る**(証跡を混ぜない)。
- 内容:

| ファイル | 内容 |
|---|---|
| `run.log` | 人間可読の実行ログ(§7.2) |
| `result.json` | 機械可読の実行結果サマリ(§7.3) |
| `stepNN_stdout.txt` / `stepNN_stderr.txt` | 各実行ステップの標準出力/標準エラー全量(NN = ステップ番号 2 桁ゼロ埋め。マスク適用済み) |
| `env_overlay.sh` | 毎回作成(§4)。ステップ終了ごとに再生成 |

### 7.2 run.log

- 各行を `[YYYY-MM-DD HH:MM:SS] ` プレフィックス付きで追記するテキスト
  (複数行メッセージは行ごとにプレフィックスを付す。マスク適用済み)。
- 記録内容(時系列): 実行開始(タイトル・パス)、作業者・確認者、
  対象ステップ番号リスト、(再開時)--start-from と復元元、各ステップの
  `--- ステップ N: タイトル ---` / コマンド / 終了コード・所要時間 /
  (ansible)ホスト別結果 / 判定(OK または NG + 理由)/ 判定内訳 /
  手動ステップの確認記録 / スキップ・中断 / RB-ONFAIL 本文、
  最後に `実行終了: <status>`。

### 7.3 result.json

UTF-8・インデント 2・非 ASCII 非エスケープの JSON(末尾改行あり。マスク適用済み)。

```json
{
  "procedure": {
    "file": "手順書パス",
    "title": "タイトル",
    "mode": "batch | interactive",
    "operator": "作業者名",
    "checker": "確認者名(なければ空文字)",
    "selected_steps": [1, 2, 3],
    "vars": {"KEY": "VALUE(secrets は *****)"},
    "secrets": ["宣言された変数名"],
    "start_from": 3,                    // --start-from 時のみ
    "resumed_env_from": "パス or null"  // --start-from 時のみ
  },
  "status": "completed | aborted",
  "started_at": "ISO8601(秒精度)",
  "finished_at": "ISO8601(秒精度)",
  "steps": [
    {
      "number": 1,
      "title": "ステップタイトル",
      "command": "実行した完全なコマンド列(手動ステップは空)",
      "criteria": "正常性基準式(手動ステップは空)",
      "status": "ok | ng | skipped | error",
      "rc": 0,                 // 未実行(手動・スキップ)は null
      "duration": 1.234,       // 秒。未実行は null
      "started_at": "ISO8601 or null",
      "finished_at": "ISO8601 or null",
      "detail": "補足(NG 理由・スキップ理由・手動確認の記録など。OK 時は空)",
      "host_results": {"web01": "ok"},   // ansible 系のみ値が入る。他は {}
      "host_matrix": false,
      "criteria_breakdown": [            // NG かつ条件 2 つ以上のときのみ非空
        {"expr": "rc == 0", "ok": true}
      ]
    }
  ]
}
```

- `steps` には**実際に処理されたステップのみ**が実行順に並ぶ。選択外(--only 等)の
  ステップ、および失敗・中断より後の**未到達ステップは含まれない**
  (`selected_steps` には含まれる)。操作者によるスキップ・中断は `skipped` として含む。
  同様に `stepNN_*.txt` も処理されたステップの分のみ作成される。
- `status` は完走(ユーザースキップ含む)なら `completed`、失敗・中断なら `aborted`。

### 7.4 実行終了時のサマリー表示

- `completed` かつスキップなし: `実行結果: 全ステップ正常終了`
- `completed` かつスキップあり: `実行結果: 完了 (スキップ n ステップあり)`
- `aborted`: `実行結果: 実行中断`
- 失敗・エラーのステップがある場合は、上記に続けて
  `— ステップ N「タイトル」で失敗` を付す(どこで落ちたかを1行目で示す)。
- 続けて**ステップ別リザルト一覧**(No. / ステップ / 結果 / rc / 所要)を表示する。
  記録のないステップは、実行対象なら `- 未実行`(中断で到達しなかった)、
  対象外なら `- 対象外` と明示し、中断位置の行に `← 中断` を付す。
- 併せてログ保存先を表示。
