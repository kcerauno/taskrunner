# 03. 正常性基準式(RB-EXPECTED)仕様

正常性基準は、コマンド実行結果(終了コード・標準出力・標準エラー)から合否を判定する
**Python 風の論理式**である。使える構文要素をホワイトリストで制限した上で評価するため、
任意コードの実行はできない。

## 1. 使用できる名前・関数

| 要素 | 型 | 意味 |
|---|---|---|
| `rc` / `exit_code` | int | コマンドの終了コード(両者は同値) |
| `stdout` | str | 標準出力の全文 |
| `stderr` | str | 標準エラーの全文 |
| `out("正規表現")` | bool | 標準出力に正規表現が(部分)マッチすれば True |
| `err("正規表現")` | bool | 標準エラーに対する同上 |
| `match("正規表現")` | bool | `stdout + "\n" + stderr` を対象に検索 |

- 正規表現は Python `re` の検索(`re.search`)。マッチ位置は任意(先頭アンカー不要)。
- `out()` / `err()` / `match()` の引数は**文字列リテラル 1 個**に限る
  (キーワード引数・変数・連結式はエラー)。
- 正規表現が不正な場合は評価時(check では検証時)にエラー。

## 2. 使用できる演算子・リテラル

- 論理: `and` / `or` / `not`、括弧 `( )`
- 比較: `==` `!=` `<` `<=` `>` `>=`、連鎖比較可(例 `0 <= rc <= 2`)
- 包含: `in` / `not in`(例 `"failed=0" in stdout`)
- 単項マイナス `-`(数値用)
- リテラル: int / float / 文字列 / True / False / None

上記以外の構文(関数定義・属性参照・添字・算術演算・内包表記など)はすべて
**基準式エラー**(CriteriaError 相当)であり、実行時はそのステップを「エラー」扱いで
中断する(→ 05 章)。エラーメッセージは「使用できない名前です」「使用できる関数は
out() / err() / match() のみです」等、原因を特定できる文言とする。

## 3. 構文上の許容

- **複数行の式を許容する**(評価時に全体を括弧で包んで解釈するため、演算子の後で
  自由に改行できる)。
- 文字列リテラル内の正規表現エスケープ(`\|` `\d` `\(` など Python として未定義の
  エスケープシーケンス)は**警告なしでそのまま**扱う(バックスラッシュ付きのまま
  正規表現に渡る)。手順書作成者は raw 文字列などの追加記法を意識しなくてよい。
- 式全体の評価結果は bool に変換して合否とする。

## 4. 評価規則

- 評価前に手順書変数の `{{VAR}}` 置換が済んでいる(→ 02 章 §10)。
- `and` / `or` は**短絡評価しない**(全オペランドを評価してから all / any で結合)。
  これは §5 の判定内訳と全体結果を必ず一致させるための仕様である。
- 省略時の既定基準は `rc == 0`。

例:

```
rc == 0
rc == 0 and out("active \(running\)") and not out("ERROR|WARN")
(rc == 0 or rc == 2) and "failed=0" in stdout
```

## 5. 判定内訳(診断)

判定 NG のとき、「どの条件で落ちたか」を示す**判定内訳**を生成する。

- 基準式を**トップレベルの `and` の結合単位**に分解し、各条件式の原文と真偽
  (OK / NG)のリストを作る。
  - `or` のまとまり(`(rc == 0 or rc == 2)` 等)や `not X` は、作成者が書いた
    1 つの判断単位として**分解しない**。
  - 複数行にまたがる条件は空白 1 個区切りの 1 行に整形して表示する。
- 条件が 1 つだけの場合は基準式そのものと同じ情報になるため**表示しない**
  (内訳は条件 2 つ以上のときのみ出力・記録する)。
- 内訳はターミナル(`[OK]` / `[NG]` 付き)と run.log に表示し、result.json の
  `criteria_breakdown`(`[{"expr": 条件式, "ok": bool}, ...]`)に記録する(→ 05 章)。
- 内訳の生成に失敗した場合(構文解析不能等)は内訳なしとして扱い、例外にはしない
  (診断は補助情報)。

## 6. 静的検証(check 用)

`runbook check` では、コマンドを実行せずに基準式の**構文のみ**を検証する:

- rc=0・空出力のダミー値で式を評価し、構文・名前・関数・リテラルの妥当性を確認する。
- `out()` 等の正規表現リテラルは `re.compile` の成否のみ確認する(マッチ判定はしない)。
