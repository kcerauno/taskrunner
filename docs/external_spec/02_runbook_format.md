# 02. 手順書フォーマット仕様

手順書は UTF-8 の Markdown ファイルである。本章はそのパース規則を定義する。
本章で「エラー」とは**パースエラー**を指し、該当した時点で全コマンド(run / list / check /
renumber)が処理を中止する(check は `NG <メッセージ>` 表示で終了コード 1、
それ以外は `エラー: <メッセージ>` 表示で終了コード 2。→ 04 章)。

## 1. ファイル全体の構造

```
(YAML frontmatter)          … 任意。runbook は解釈しない(§2)
# 手順書タイトル             … 任意。タイトルとして採用(§3)
前書きの自由記述
```runbook フェンス          … 任意。共通設定(§4)
## ステップ1見出し           … 「## 」見出し 1 つ = 1 ステップ(§5)
  (### RB-* セクション群)
## ステップ2見出し
  ...
```

- 行の走査はコードフェンス(行頭の空白 + ` ``` ` で始まる行)を追跡しながら行い、
  **フェンス内部の行は見出し(`#` / `##` / `###`)として解釈しない**
  (bash コメント `### ...` などを見出し誤認しないため)。
- フェンスの開始行は `^\s*```\s*(\S*)` にマッチする行。直後の語を言語名(小文字化)とする。
  閉じられていないフェンスがあればエラー(「コードフェンス ``` が閉じられていません」)。
- 通常ステップ(`## ` 見出し)が 1 つもなければエラー。

## 2. frontmatter

- ファイルの **1 行目**が `---` の場合、次の `---` 行までを YAML frontmatter とする。
  - 閉じ `---` がなければエラー。
  - YAML として辞書でなければエラー。
- frontmatter は**一般的な Markdown メタデータとして読み飛ばすだけ**で、runbook は
  一切解釈しない。
- ただし fail-loud のため、frontmatter に runbook の設定キー
  **vars / ansible / secrets** のいずれかが含まれていたらエラーにする
  (「書いたのに効かない」事故防止。エラーメッセージで ```runbook フェンスへの記載を案内する)。

## 3. タイトル

優先順位:

1. 共通設定(```runbook フェンス)の `title` キー(文字列化して使用)
2. 最初のステップより前にある最初の `# 見出し`(フェンス外)
3. どちらもなければファイル名(拡張子なし)

## 4. 共通設定(```runbook フェンス)

最初の `## ` 見出しより**前**(前書き)に置いた言語名 `runbook` のコードフェンスの中身を
YAML 辞書として読む。コードフェンスは CommonMark 標準要素なので、どの Markdown
プレビューでも中身が表示される(これがフェンス方式を採る理由)。

````markdown
```runbook
title: 〇〇作業手順        # 任意
vars:                      # 任意: 手順書変数
  TARGET: web01
  DB_PASS: xxxx
ansible:                   # 任意: ansible 系ステップの共通既定
  target: web
  extra_args: "--forks 10"
  host_matrix: true
secrets: [DB_PASS]         # 任意: マスク対象変数の宣言
```
````

規則:

- ```runbook フェンスが前書きに**複数**あればエラー(1 つにまとめる)。
- 中身が YAML の辞書でなければエラー(空なら空辞書扱い)。
- **ステップ内(最初の `## ` 以降)のどの位置にあっても** ```runbook フェンスはエラー
  (前書き専用。どのセクション内でも検出する)。
- 認識するキーは `title` / `vars` / `ansible` / `secrets`。
  (`share_env` は v0.5.0 で廃止。環境変数の引き継ぎは常時有効。)
- これ以外の未知キーは**無視される**(互換のためパースはエラーにしない)が、
  `check` が警告する。特に `timeout` は共通設定では効かず、タイムアウトの既定は
  「なし(無制限に待つ)」のため、RB-LOCALDEF に書くよう案内する。

各キーの仕様:

| キー | 型 | 仕様 |
|---|---|---|
| `title` | 任意型 | 文字列化してタイトルに使用 |
| `vars` | 辞書 | キー・値とも文字列化して手順書変数とする。CLI の `--var KEY=VALUE` が同名変数を上書きする |
| `ansible` | 辞書 | 使用可能キー: `target` / `extra_args` / `host_matrix`。**`inventory` を書くとエラー**(共通デフォルト禁止。エラーメッセージで各ステップでの明示指定を案内する)。辞書でなければエラー |
| `secrets` | 文字列のリスト | リスト以外・文字列以外の要素はエラー。宣言した変数名が(vars と --var を合わせた)変数に**未定義ならエラー**。→ 05 章 §5 |

## 5. ステップ

- フェンス外の `## ` 見出し(`^##\s+(.+?)\s*$`)1 つが 1 ステップ。
  見出しから次の `## `(またはファイル末尾)までがそのステップの本文。
- ステップ番号は**記載順に 1 から採番**する(実行順は常に記載順)。
- 見出しテキストが「番号 + 区切り + タイトル」形式(`^(\d+)\s*[.．:：]\s*(.*)$`、
  区切り記号の後の空白は任意、残りテキストが空でないこと)の場合、番号を
  「見出し番号」として分離し、タイトルは残り部分とする。見出し番号は表示・検証用であり、
  **実行順には影響しない**。実際の順序と不一致の場合 check が警告する(→ 04 章)。

### 5.1 ステップ内セクション

ステップ本文はフェンス外の `### 見出し` で以下のセクションに分割する。
セクション名の照合は**大文字小文字を区別しない**。

| セクション | 必須 | 内容 |
|---|---|---|
| `### RB-DESCRIPTION` | 手動ステップのみ必須 | 作業説明(自由記述)。フェンス外テキストを採用 |
| `### RB-LOCALDEF` | 任意 | ステップ個別設定(YAML 辞書。§5.2) |
| `### RB-CMD` | 通常ステップで必須 | 実行コマンド(§6〜8) |
| `### RB-EXPECTED` | 任意 | 正常性基準式(→ 03 章)。最初のコードフェンスの中身、フェンスがなければフェンス外テキスト。空なら既定 `rc == 0` |
| `### RB-ONFAIL` | 任意 | 失敗中断時に表示する作業者向けガイダンス(自由記述)。表示のみで自動修復はしない |

- 上記 5 つ以外の `###` 見出しがステップ内にあればエラー(使用可能セクション名を列挙して案内)。
- ステップ見出し直後から最初の `###` までの行は無視される(自由記述の余白)。
- **セクションの記載順はパース結果に影響しない**(順不同)。ただし手順書は上から順に
  読まれるものなので、上表の順(RB-DESCRIPTION → RB-LOCALDEF → RB-CMD → RB-EXPECTED
  → RB-ONFAIL)を**推奨順**とする。RB-LOCALDEF を RB-CMD より前に置くことで、
  読み手は「何をするか(説明)→ どこでどう実行するか(ansible か否か・inventory・
  target・timeout)→ 実際に走るもの(コマンド)→ 合否の判定 → 失敗時の行動」の順に
  読める。ansible 系ステップではフェンスの言語名より先に実行先が目に入るため、
  対象環境の取り違えに気付きやすい。

### 5.2 RB-LOCALDEF

最初のコードフェンスの中身(なければフェンス外テキスト)を YAML 辞書として読む。
辞書でなければエラー。使用可能キー以外があればエラー。

| キー | 型 | 意味 |
|---|---|---|
| `timeout` | 数値 | ステップのタイムアウト秒。超過時はプロセスグループごと強制終了し、ステップは「エラー」扱い(→ 05 章) |
| `cwd` | 文字列 | コマンド実行時のカレントディレクトリ |
| `ansible` | 辞書 | ansible 系ステップの設定。共通設定の `ansible` に対しキー単位で上書きマージされる。使用可能キー: `inventory` / `target` / `extra_args` / `host_matrix`(それ以外はエラー)。`host_matrix` は bool でなければエラー |

### 5.3 手動ステップ(RB-CMD なし)

RB-CMD セクションがないステップは**手動ステップ**(目視確認・手作業・関係者連絡などを
手順に組み込むためのもの)となる。

- **RB-DESCRIPTION が必須**(書き忘れとの区別のため。なければエラー)。
- RB-EXPECTED があればエラー(判定対象のコマンドがない)。RB-LOCALDEF があればエラー。
- 実行時は説明を表示し、作業者の完了確認(`y` の明示入力)を待つ(→ 04 章 §3.4)。

## 6. RB-CMD とランナー判定

RB-CMD 内のコードフェンスの扱い:

- フェンスが 1 つ以上ある場合: **全フェンスの中身を改行で連結**したものをコマンド列とする。
  フェンスがない場合はフェンス外テキストをコマンド列とする。連結結果が空ならエラー。
- フェンスの言語名によってランナーを決める:
  - `ansible` → ansible ad-hoc ランナー(§7)
  - `playbook` または `ansible-playbook` → playbook ランナー(§8)
  - それ以外(`bash` など。言語名なしも含む)→ shell ランナー
- **ansible 系フェンスと他言語フェンスの混在、および ansible 系 2 種の混在はエラー**
  (1 ステップ = 1 ランナー)。

shell ランナーのコマンド列は、変数置換(§10)の後 `/bin/bash -c` にそのまま渡される
(複数行可。実行仕様は 05 章)。

## 7. ansible ad-hoc ランナー(```ansible フェンス)

フェンスの中身は**リモートで実行するコマンド**であり、ansible の
`-m shell -a '<コマンド>'` として実行される。組み立てた 1 本のコマンド文字列を
shell ランナーと同じ方法でローカル実行する。

### 7.1 設定の解決

ステップの ansible 設定は「共通設定の `ansible`」に「RB-LOCALDEF の `ansible`」を
キー単位で上書きマージして得る。`inventory` / `target` / `extra_args` の値には
変数置換(§10)を適用する。

- **inventory は共通設定で持てない**(§4)ため、行内指定(§7.3)か RB-LOCALDEF で
  **毎回明示**しなければならない。未指定はエラー。
- target も未指定はエラー(こちらは共通設定の既定が使える)。

### 7.2 コマンド組み立て(設定指定スタイル)

```
ansible <target> -i <inventory> [-e '<JSON>'] [<extra_args>] -m shell -a '<リモートコマンド>'
```

- `<target>`・`<inventory>`・`<JSON>`・`<リモートコマンド>` はシェルクォートして埋め込む。
  `<extra_args>` は**クォートせずそのまま**連結する(複数オプションを書けるようにするため)。
- `-e '<JSON>'` は手順書変数が 1 つ以上あるときのみ付与。JSON は全変数の
  `{"KEY": "VALUE", ...}`(ASCII エスケープなし)。

### 7.3 行内指定スタイル(フェンス 1 行目が `ansible ` で始まる場合)

````markdown
```ansible
ansible db -i inventories/db.ini -e HOGE=ADHOC
df -h /
```
````

- 1 行目(`ansible` + 空白、または `ansible` のみで始まる行)を**起動指定**として使い、
  設定側の target / inventory は**無視**する。`ansible` に続く残り部分に変数置換を適用し、
  そのまま引数列として使う。残り部分が空ならエラー。
- 2 行目以降がリモートコマンド。空ならエラー。
- 組み立て: `ansible [-e '<JSON>'] <起動指定の残り> [<extra_args>] -m shell -a '<リモートコマンド>'`
  - 自動付与の `-e JSON` を**先**に置くため、行内に書いた `-e` が後ろ = ansible の規則で
    **優先**される(同名変数の実行時上書きに使う)。

### 7.4 変数と jinja2 の関係(重要)

**フェンス内のリモートコマンドには runbook の `{{VAR}}` テキスト置換を行わない**
(行内指定の 1 行目だけは例外的に置換する)。手順書変数は §7.2/7.3 の `-e JSON` として
ansible に渡し、ansible 側の jinja2 に `{{VAR}}` を解決させる。これにより
`{{ inventory_hostname }}` 等の jinja2 記法と手順書変数が同じ記法のまま共存できる。

## 8. playbook ランナー(```playbook / ```ansible-playbook フェンス)

フェンスの各行(空行と `#` 始まりの行は無視)は
**「ansible-playbook に渡す引数列」そのもの**である。プレイブックのパスに続けて
オプションを直接書ける:

````markdown
```playbook
-i inventories/web.ini deploy.yml -e HOGE=PIYO --check
-i inventories/db.ini migrate.yml
```
````

- 有効行が 0 ならエラー。
- 各行に変数置換(§10)を適用する(行はコントローラ側の値のため)。
- 行ごとに次を組み立てる:

```
ansible-playbook [-i <inventory>] [-l <target>] [-e '<JSON>'] [<extra_args>] <行の内容>
```

  - **行内に `-i` / `--inventory`(`-iINV` / `--inventory=INV` 形式含む)があれば、
    設定側 inventory は付与しない**(ansible は複数 `-i` を「結合」するため、二重付与は
    事故のもと)。行内にも設定側にも inventory がなければエラー(行の内容をエラーに含める)。
  - `target` 設定があれば `-l`(limit)として付与。
  - `-e '<JSON>'` は §7.2 と同じ(行内の `-e` が後ろ = 優先)。
- 複数行は ` && ` で連結して 1 コマンドにする(fail-fast: 途中の行が失敗したら以降は
  実行されない)。

## 9. # RB-ROLLBACK(廃止。書かれていたらエラー)

切り戻し(ロールバック)はツールの機能として**持たない**。切り戻しが必要な作業は
別ファイルの手順書として作成し、人間の判断で実行する(01 章の原則)。

- フェンス外のレベル 1 見出し `# RB-ROLLBACK`(大文字小文字非区別、
  `^#\s+RB-ROLLBACK\s*$`)を検出したら**パースエラー**にし、別ファイルの手順書として
  作成するよう案内する。黙って通常見出しとして扱わない(fail-loud 原則)。
- フェンス内部の `# RB-ROLLBACK` 行は通常のコード片なのでエラーにしない。

## 10. 変数置換

- 記法: `{{VAR}}`(`{{ VAR }}` のように前後空白可)。変数名は
  `[A-Za-z_][A-Za-z0-9_]*`。
- 変数の値は「共通設定 `vars`」を CLI `--var KEY=VALUE` で上書き・追加したもの。
- 置換対象:
  - shell ランナーのコマンド列
  - 正常性基準式(全ランナー)
  - ansible の設定値(inventory / target / extra_args)
  - ansible 行内指定の 1 行目(起動指定)
  - playbook フェンスの各行
- 置換**しない**もの: ansible フェンスのリモートコマンド(§7.4)。
- 置換対象に**未定義**の `{{VAR}}` があればエラー(ステップ番号・タイトル付きで、
  vars か --var での定義を案内)。

## 11. パースエラーメッセージの規約

ステップに起因するエラーは「ステップN「タイトル」: 〜」の形式で位置を示す。
ファイル全体に起因するエラー(ステップなし・`# RB-ROLLBACK` の検出等)はファイルパスを先頭に付す。
いずれも原因と**修正方法(どこに何を書くべきか)**を 1 文で案内することを原則とする。
